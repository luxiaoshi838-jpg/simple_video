# 简播 1.0.12 维护日志

日期：2026-09-04

1. 用户真机测试 1.0.11：微信“更多打开方式 → 简播”可以进入外部打开流程，但退出播放后点击“授权所在文件夹”时，系统 SAF 文件夹选择器落在“内部存储”根目录，并提示“无法使用此文件夹 / 为保护您的隐私，请选择其他文件夹”，底部“使用此文件夹”为灰色。
2. 确认这是 Android 11+ 对 SAF 的系统限制：内部存储根目录本身不能被授予树权限。1.0.11 在无法从微信 URI 推导父目录时直接用 `OpenDocumentTree(null)` 回退到根目录，导致用户看见一个不可直接授权的界面；该回退设计不够明确。
3. 用户进一步明确要求：无论最终能否取得目录权限，“加入这个视频所在文件夹？”弹框内至少必须显示该视频的真实文件位置与真实父文件夹位置；不能只显示泛化提示。
4. 建立分支 `agent/v1.0.12-external-parent-resolution`，基线为 1.0.11 main。
5. 新增 `ExternalUriLocationResolver.kt`，对外部 URI 做只读、尽力而为的真实路径解析，顺序为：`file://` 路径 → ExternalStorageProvider documentId → MediaStore `RELATIVE_PATH/VOLUME_NAME/DISPLAY_NAME` → provider 暴露的 `_data` → 打开文件描述符后读取 `/proc/self/fd/<fd>` 符号链接。
6. 解析器不伪造路径：只有获得实际文件系统路径时才显示“文件位置/所在文件夹”。若 Android 或微信 Provider 隐藏真实物理路径，则弹框明确显示“真实路径不可读取”，同时显示原始 `content://...` URI，便于继续诊断。
7. 对 `/storage/emulated/0/...` 路径统一显示为 `内部存储/...`；如果真实父目录位于共享存储中，则把该父目录转换为 ExternalStorageProvider document URI，用作系统 `OpenDocumentTree` 的初始位置，避免再次无条件落到内部存储根目录。
8. 若 URI 无法解析真实路径但来源看起来属于微信，并且共享存储 `Android/media/com.tencent.mm` 实际存在，则系统选择器优先定位到该微信共享目录；不把该目录冒充为真实视频所在目录。
9. `ExternalOpenActivity.kt` 的“加入这个视频所在文件夹？”弹框固定显示：`文件位置：...`、`所在文件夹：...`。路径文字可长按选择复制。若两者任一无法解析，额外显示“来源 URI：content://...”。
10. 若解析出的父目录属于 `/data/...` 等其他应用私有存储，弹框明确说明 Android 只允许临时读取当前视频，不能取得整个父目录权限，并隐藏无意义的“授权所在文件夹”按钮。
11. 若无法直接定位父目录但仍可手动授权，按钮改为“手动选择具体文件夹”，并明确提示：内部存储根目录本身不能授权，需要进入具体子文件夹后再点“使用此文件夹”。
