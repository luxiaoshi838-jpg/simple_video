# 简播 1.0.11 维护日志

日期：2026-09-04

1. 用户反馈 1.0.10 的“授权微信隐藏视频扫描”仍主要重复发现已经被普通扫描找到的视频，没有解决目标大文件发现问题。
2. 审计 `WechatHiddenVideoScanner.kt`：1.0.10 主要依赖 `MediaStore.Files.DATA` 路径集合排除已索引文件；Android 新版上该路径信息可能不可用或不完整，因此同一物理文件会以 `media:<id>` 和 `wechat-file:<path>` 两套 ID 再次进入列表。决定改为跨扫描入口记录统一的 `storageIdentity`，按实际存储位置去重。
3. 用户提出新的主路线：微信“更多打开方式”应能直接选择简播；简播打开该视频后，应利用这个文件引导取得其所在文件夹的长期访问权限。确认 Android 不能凭单文件 URI 静默获得父目录权限，因此实现为：先用微信授予的单文件 URI 直接播放；退出播放后显示“授权所在文件夹”，再由系统 `OpenDocumentTree` 让用户确认一次，SAF 权限持久保存。
4. 若外部 URI 来自 `com.android.externalstorage.documents` 且能解析 documentId，则从文件 documentId 推导父目录 documentId，并把系统文件夹选择器尽量预定位到父目录；若微信只提供自身临时 `content://` URI，则不伪造路径，由用户在系统选择器中确认目录。
5. 建立工作分支 `agent/v1.0.11-external-open-folder-access`，基线为 1.0.10 主分支。
6. `Models.kt` 新增 `folderLocation` 与 `storageIdentity`；`VideoGroup.location` 从组内视频读取可用目录位置；新增 `ExternalOpenRequest` 保存外部打开的视频与可选父目录初始 URI。
7. `LibraryRepository.kt`：MediaStore 自动扫描开始记录共享存储卷、相对目录位置和稳定存储位置；SAF 手动目录开始解析并记录文档树位置；新增 `resolveExternalOpen()` 解析 `ACTION_VIEW`/`ACTION_SEND` 的外部视频 URI、名称、元数据和可推导的父目录。
8. `MediaStoreFilesVideoFallback.kt`：补齐目录位置和 `storageIdentity`，保证兜底 MediaStore 扫描也能参与跨入口去重。
9. `WechatHiddenVideoScanner.kt`：除原有 MediaStore DATA 排除外，新增与已有库的 `storageIdentity` 对比；直接文件扫描也保存真实共享存储位置。这样即使新 Android 不返回可靠 DATA，也不会仅因扫描入口不同重复显示同一文件。
10. 新增 `ExternalOpenActivity.kt`：接收外部视频后直接调用现有 `PlayerScreen` 播放；退出后提供“授权所在文件夹”与“仅播放这一次”两种操作。文件夹授权成功后调用现有 `LibraryRepository.addManualTree()` 持久保存 SAF 权限。
11. `AndroidManifest.xml` 新增 `ExternalOpenActivity`，注册 `ACTION_VIEW` 与 `ACTION_SEND`，接收 `video/*`、`application/octet-stream`、`application/mp4`、`application/x-matroska`，用于覆盖微信把大视频当普通文件发送的情况。
12. 用户补充 UI 要求：进入简播文件夹后，“X 个视频”后面应显示该文件夹的位置。`MainActivity.kt` 的文件夹详情顶部已改为 `X 个视频 · 文件夹位置`；位置过长时最多两行并省略尾部。
13. 文件夹位置来源规则：MediaStore 使用共享存储相对路径并显示为 `内部存储/...`；SAF 使用可解析的文档树路径；微信直接文件扫描使用共享存储实际父目录；无法获得真实路径时不伪造。
14. 版本升级为 `1.0.11` / `versionCode=12`，applicationId 仍为 `com.luxiaoshi.jianbo`。`build.gradle.kts` 保持正确依赖 `androidx.compose.material3:material3`，没有重复 1.0.9/1.0.10 的错误坐标。
15. `AGENTS.md` 新增固定规则：外部单文件 URI 不得假装拥有父目录权限；目录级权限必须经系统 SAF 确认；文件夹详情必须展示可获得的位置；隐藏扫描必须按实际存储位置去重。
